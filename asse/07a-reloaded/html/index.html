What is Reverse Beamforming?

Beamforming: several antennas send the same signal, each a little later than its neighbour. The waves add up in one direction (5G, Wi-Fi).

Reverse beamforming: several antennas receive one signal. From the differences in arrival time, we compute where it came from (angle of arrival).

Like the Compiler, and Yet Different

Same

What instead of How

Humans describe the goal, the machine generates the code.

Scepticism at first

“Computers cannot write programs”, in 1952 as today.

More demand

Cheaper software → more software, not less work.

Different

Deterministic vs. probabilistic

Nobody reads compiler output, because it is generated deterministically. AI output must be checked, at least indirectly.

Formal vs. natural language

Prompts are ambiguous, like natural-language specifications.

Speed

Three generations of tools since 2021: autocomplete, agents, autonomous agents.

So the work does not disappear. It moves to verifying and delivering.

From Software to Systems

After the focus on individual components in the first half of the semester, we now concentrate on interactions between components. Specifically, we will discuss the trade-offs that are involved in designing these interfaces and interactions.

Many of the concepts that you saw in the course up to now apply again!

Software architecture consists of the structure of the system, combined with architecture characteristics (“-ilities”) the system must support, architecture decisions, and finally design principles.

„Everything in software architecture is a trade-off.“

„WHY is more important than HOW.“

and systems!

(Selected) Architecture Characteristics

Recap: First Half of the Semester

Architecture Characteristic

Definition

Reliability

Refers to the probability of a failure free operation of the system for a specific period

Responsiveness

The ability of a system to complete assigned tasks within a certain time

Availability

Refers to the percentage of time a system is available for its user in a given period

Fault Tolerance

The ability of a system to continue operating in the event of a failure within some of its components

Scalability

The ability to handle large numbers of concurrent users without serious performance degradation

Elasticity

The ability to handle bursts of requests

Data integrity

Refers to the accuracy and consistency (validity) of data over its lifecycle

Data consistency

Refers to whether the same data kept at different places do or do not match

Adaptability

Adaptability refers to the ability to easily change the system according to the requirements.

Extensibility

Refers to the ability to extend a system and the effort needed to implement the extensions

Testability

The degree to which a software artifact supports testing in a given test context

Deployability

The extent to which something is deployable

Overall Goal: Multi-Level View on Interoperability

From Software to Systems

Coupled through proprietary interface. Changing a single bit might break interaction. Little tolerance to changes on either side.

00100010111010010100111010111000100

Coupled Bits

Coupled through open interface and data format. Changing URI handled through uniform interface and HATEOAS. Changing schema might break it.

GET /temp Accept: application/json

Coupled Schemas

Coupled through open interface and documented media type. Change in media type might break it, gracefully.

GET /temp Accept: application/miele+json

Coupled Types

Coupled through open interface, documented media type, and agreed-upon standard vocabulary. Changing meaning of vocabulary terms might break it.

GET /temp Accept: application/ld+json

Coupled Meanings

Coupled through natural language that a statistical model interprets at run time. A different wording or a different model might change the result.

“How warm is it in the meeting room right now?”

Coupled Language

/temp a saref:TemperatureSensor

{"@context": "https://saref.etsi.org/core/Temperature.jsonld",

"Temperature": "20"}

MCP server

AI agents

As the architect of a (distributed) (information) system, you should be aware of different ways of how to consciously manage the interoperability of system components.

This is relevant in a (technology) world with increasingly heterogeneous and autonomous components.
